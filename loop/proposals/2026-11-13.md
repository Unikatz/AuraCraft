## Items

### 1. Pet gets in the way when placing a block

- Source: feedback issue 1 (bug, rated 3 of 5). One tester.
- Problem: when Doggy or Mew stands in the square where a block should go, the block is not placed and the game says nothing. The pet follows the player, so this happens right where the player is building. Also, if the player's aim touches the pet, pressing Place pets it instead of placing.
- Proposed change: when a pet (Doggy or Mew only) is in the target square, the pet hops to the nearest free square beside it and the block is placed. With a block in hand, Place aims through the pet to the block behind it; Use still pets it. For any other creature in the way, show a short message ("Something is in the way") so the game is never silent. Add a test for it.
- Effort: about half a day, test included.
- Risk: low. No new blocks, nothing saved changes. Small risk that the pet hops somewhere odd in a tight space; the test covers a walled-in pet (then the block is simply not placed, with the message).
- Recommendation: approve.

### 2. Glass door opens as one door

- Source: feedback issue 2 (idea, phone, rated 2 of 5). One tester said "The glass door is not very easy to use". The tester did not say why.
- Problem: the door in the starter house is 2 Glass Rock blocks, one on top of the other. Each block opens on its own, so the player has to aim and press Use twice to walk through, and twice again to close it. On a phone that means aiming twice with a thumb. This is the dev's reading of the code, not something the tester spelled out.
- Proposed change: pressing Use on a Glass Rock block also opens or closes the one Glass Rock block directly above or below it, so a 2-high door works with one press. Only that one neighbour, never a whole wall. The "step out of the doorway first" check stays for both blocks. Add a test.
- Effort: 2 to 3 hours, test included.
- Risk: low. Same blocks, nothing saved changes. Side effect: two glass windows stacked on top of each other would also open together.
- Recommendation: approve. It is the smallest change that could help, and the "Tell us" reason "Doors or furniture" will show whether doors are still hard afterwards.

### 3. A wooden door (doors in other materials)

- Source: feedback issue 2, same note: "Can you add different material doors". One tester.
- Problem: the only door is the glass one.
- Proposed change, one-week slice: one new block, a Wood Door, that opens and closes with Use like the glass one. Other materials would wait until testers react.
- Effort: about 1 day, test included.
- Risk: medium, and two points may make it the owner's call:
  - It adds new block types to saved worlds. The save layout is unchanged, but a world with a Wood Door in it would probably not load properly in the older `stable` version, so a rollback after release could break those worlds. The dev has not tested this. (The Wood Table and Pet House were added the same way on 7 Nov.)
  - A wooden door is a familiar Minecraft item. The charter sends anything that moves the game closer to Minecraft to the owner.
- Recommendation: do not build this week. Do item 2 first and see whether doors are still a complaint. The dev flags the two points above for the Approver to judge whether this needs the owner.

### 4. Test report shows "0 checks passed" for 5 of 6 test files (dev review)

- Source: dev review. No tester asked for this.
- Problem: `tests/run.sh` counts lines that start with PASS, but only the guide test prints such lines. The other five print their own text, so the report reads "0 checks passed" for them even though they ran and did not fail. The pass or fail result is still right; only the count misleads whoever reads the report before a release.
- Proposed change: make the five tests print a PASS line for each check, so the counts are real. No change to the game file.
- Effort: about 1 hour.
- Risk: very low. Touches only `tests/`.
- Recommendation: approve if there is room; it is not urgent.

### Escalation to the owner: item 3 (reply by Tuesday 17 November 2026)

What the owner must decide: whether Aura Isles should get doors in other materials, starting with a Wood Door, and if so in what style.

Why it is the owner's:

- Direction: the charter sends "anything that moves it closer to Minecraft" to the owner, and a wooden door is a familiar Minecraft item.
- Saved worlds: the save layout does not change, but a world containing the new block would probably not load in the older `stable` build, so a rollback after release could break those worlds. This is untested.
- Evidence: one tester asked, in one note.

Options:

- a. Not now. Ship the glass-door fix (item 2) first and revisit when testers, including the "Doors or furniture" reason on "Tell us", show whether doors are still a complaint.
- b. Approve one Wood Door for a later week, on condition that the dev first tests and reports what happens to a world with new blocks when the game is rolled back.
- c. Yes to more doors, but in a material and look that is Aura Isles' own rather than a plain wooden door. The owner names the direction and the dev re-proposes.

Approver's recommendation: a. The evidence is one request, and the same tester's stronger complaint (ease of use) is addressed by item 2. The Approver recommends the rollback test from option b whichever option the owner picks.
